## Summary

Add a "Close" button to each open position row in the positions table, allowing the user to close a position by placing an opposite-direction market order for the full position size. Reuses the existing F5 order placement endpoint — no new backend work required.

### User Story

> As a **developer**, I want to **close an open position directly from the positions table** so that **I can quickly exit a trade without manually constructing an opposite market order in the order entry form**.

### Business Value

A "Close Position" action is a fundamental trading UX expectation. Without it, users must mentally calculate the opposite side and full size, then navigate to the order form — error-prone and slow. This is a low-effort, high-impact UX improvement that completes the POC's position lifecycle.

---

## Problem Statement

The positions table (F2) is currently read-only. To close a position, a user must manually place an opposite-direction market order via the order entry form (F5), matching the exact position size. This is cumbersome and error-prone. A one-click "Close" button on each position row would streamline the workflow.

---

## Requirements

### Functional Requirements

1. "Close" button displayed on each open position row in the positions table
2. Clicking "Close" opens a confirmation dialog showing: asset, side being closed, and size
3. On confirmation, a market order is placed via the existing `POST /api/orders` endpoint with:
   - `asset`: the position's asset (e.g., "BTC")
   - `side`: opposite of the position's side ("sell" if Long, "buy" if Short)
   - `orderType`: "market"
   - `size`: the position's full size (absolute value)
4. Success toast shown after order submission succeeds
5. Error toast shown if the order submission fails, with meaningful error message
6. Row-level loading state: Close button disabled with spinner while the API call is in flight
7. After successful close, the dashboard refresh is triggered to update positions and orders tables
8. Close button disabled while any operation is in flight for that position

### Non-Functional Requirements

- Reuses the existing F5 order placement endpoint and signing flow — no new backend endpoints
- Close operation should complete within the same latency as a normal market order placement
- UI must remain responsive during the API call

---

## User Flow

### Happy Path — Close Position

1. User has an open Long BTC-PERP position visible in the positions table
2. User clicks "Close" button on the position row
3. Confirmation dialog appears: "Close Long BTC-PERP position? This will place a market Sell order for 0.005 BTC."
4. User confirms
5. Close button shows spinner; row is in loading state
6. Market sell order is submitted via `POST /api/orders` using existing F5 flow
7. Success toast: "Position close order submitted"
8. Dashboard refreshes — position disappears (or updates) once the order fills

### Error States

| Scenario | Expected Behavior |
|----------|-------------------|
| Insufficient margin for close order | Error toast with Hyperliquid error message |
| Position already closed (race condition) | Error toast; dashboard refresh shows updated state |
| Network error during submission | Error toast: "Failed to close position" |
| API signing error | Error toast with signing error details |

## Technical Considerations

### API Endpoints

No new endpoints — reuses `POST /api/orders` from F5.

| Method | Route | Description |
|--------|-------|-------------|
| POST | `/api/orders` | Place a market order (opposite side, full size) to close the position |

### Close Request Body (constructed by frontend)

```json
{
  "asset": "BTC",
  "side": "sell",
  "orderType": "market",
  "size": 0.005
}
```

### Key Components

| Component | Action |
|-----------|--------|
| `PositionsTableComponent` | Add Close button, loading state, confirmation dialog, event emitter |
| `OrderService` (Angular) | Reuse existing `placeOrder()` method |
| `ConfirmDialogComponent` | Reuse from F5/F6 for confirmation |
| `DashboardComponent` | Handle refresh trigger from positions table |

### Frontend Changes Only

This PBI requires **no backend changes**. The close action constructs a `PlaceOrderRequest` and calls the existing endpoint. All changes are in:

- `positions-table.component.html` — add Close button column, loading state, context menu
- `positions-table.component.ts` — add close logic, dialog, service injection, event emitter
- `positions-table.component.scss` — button and loading spinner styles
- `dashboard.component.ts` — wire positions table refresh event (if not already connected)

### Tech Stack Compliance

- **Frontend**: Angular 19 standalone — extends existing positions table component
- **Dependencies**: MatDialog, MatSnackBar, MatProgressSpinner, MatButton (all already imported in the project)
- **No new packages required**

## Acceptance Criteria
