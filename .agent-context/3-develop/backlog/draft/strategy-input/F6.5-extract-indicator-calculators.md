## Summary

Extract all indicator calculations from `BacktestMarketContextBuilder` private methods into a dedicated `TradingApp.Indicators` project as standalone, pure-math static classes. Fix incorrect RSI (Wilder smoothing) and EMA (SMA seed) algorithms. Add MACD and Bollinger Bands calculators. This unblocks F7 (correct EMA for trend filters), F8 (MACD calculation), and future Bollinger-based conditions.

### User Story

> As a **developer**, I want **indicator calculations (EMA, RSI, ATR, MACD, Bollinger Bands) extracted into a dedicated `TradingApp.Indicators` project as standalone, pure-math static classes** so that **calculations are independently testable, reusable across live and backtest contexts, and new indicators can be added without modifying existing services**.

### Business Value

Foundation for correct and trustworthy strategy evaluation. Without this, F7 ships with incorrectly-seeded EMA, F8 has no MACD calculation to call, and every future indicator requires growing `BacktestMarketContextBuilder`. Correcting RSI/EMA to match TradingView ensures backtest results align with what traders see on charts.

---

## Problem Statement

All indicator calculations are currently private methods inside `BacktestMarketContextBuilder`. This creates several problems:

1. **Not reusable** — When the live `MarketContextBuilder` is built, all calculation code would need to be duplicated.
2. **Not independently testable** — EMA/RSI/ATR math can only be tested by constructing the full builder, feeding candles, and calling `Build()`.
3. **Incorrect RSI algorithm** — The current implementation uses simple averaging of gains/losses. The industry-standard RSI (Wilder smoothing) uses an exponential method that produces different values. Current backtest RSI will not match TradingView, Pine Script, or other platforms.
4. **Incorrect EMA seeding** — The current EMA uses the first candle's close as the seed, regardless of the period. The standard approach seeds with the SMA of the first `period` values, which produces noticeably different results for longer periods (e.g., EMA 200).
5. **MACD is blocked** — Infrastructure for MACD exists in `IndicatorContext` and `IndicatorExtractor`, but the actual calculation cannot be added without growing `BacktestMarketContextBuilder` further.
6. **Bollinger Bands not available** — No Bollinger Bands calculation exists. Required for future strategy conditions.

## Requirements

### Functional Requirements

1. Create a new `TradingApp.Indicators` class library project containing pure-math static calculator classes
2. Create a new `TradingApp.Indicators.Tests` test project with comprehensive unit tests for each calculator
3. Implement `EmaCalculator` as a static class that calculates EMA using SMA-seeded initialisation
4. Implement `RsiCalculator` as a static class that calculates RSI using Wilder smoothing
5. Implement `AtrCalculator` as a static class that calculates ATR using true range
6. Implement `MacdCalculator` as a static class that returns MACD line, signal line, and histogram
7. Implement `BollingerBandsCalculator` as a static class that returns upper band, middle band (SMA), and lower band
8. Refactor `BacktestMarketContextBuilder` to delegate to the new calculator classes instead of using private methods
9. Update `IndicatorContext` population in `BacktestMarketContextBuilder` to include MACD values when required by strategy config

### Non-Functional Requirements

- Each calculator must be a static class with no dependencies — pure functions only (decimal in, decimal out)
- Calculator methods must handle insufficient data gracefully (return null or partial results for warmup periods)
- All calculators must be verified against reference values from TradingView or known reference implementations
- No regression in existing backtest results beyond expected improvements from algorithm corrections (RSI/EMA fixes will intentionally change output values)

### Algorithm Corrections

**RSI — Wilder Smoothing:**
Current: simple `gains / losses` over last N bars.
Correct: Seed with simple average of first N periods, then apply `((prevAvg * (period - 1)) + currentValue) / period` for subsequent values.

**EMA — SMA Seed:**
Current: first candle close used as seed regardless of period.
Correct: SMA of first `period` closes used as seed, then apply standard EMA formula from period index onward.
