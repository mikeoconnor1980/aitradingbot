# Task Checklist: F6.1 — Close Position

## Overview

Add a "Close" button to each open position row in the positions table, allowing the user to close a position by placing an opposite-direction market order for the full position size. Frontend-only changes reusing the existing F5 order placement endpoint.

## PBI Details

**PBI ID:** Draft  
**Status:** Draft  
**Implementation Phase:** 6  
**Risk Level:** Low  
**Depends On:** F2 (Positions Table), F5 (Order Placement), F6 (Order Management)

### User Story

> As a **developer**, I want to **close an open position directly from the positions table** so that **I can quickly exit a trade without manually constructing an opposite market order in the order entry form**.

### Acceptance Criteria

- [ ] **Given** I have an open position in the positions table, **When** I view the positions table, **Then** I see a "Close" button on each position row
- [ ] **Given** I click Close on a Long BTC-PERP position, **When** the confirmation dialog appears, **Then** it shows the asset, side (Long), and size, and states it will place a market Sell order
- [ ] **Given** the confirmation dialog is shown, **When** I confirm, **Then** a market order is placed via `POST /api/orders` with opposite side and full position size
- [ ] **Given** the confirmation dialog is shown, **When** I dismiss/cancel the dialog, **Then** no action is taken
- [ ] **Given** the close order is submitted successfully, **When** the API response is received, **Then** a success toast is shown and the dashboard data refreshes
- [ ] **Given** the close order fails, **When** the error response is received, **Then** an error toast is shown with a meaningful message
- [ ] **Given** a close API call is in flight, **When** I look at that position row, **Then** the Close button is disabled and a spinner is shown

## Objectives

- Add a Close button to each position row in the positions table
- Implement confirmation dialog before submitting the close order
- Reuse existing `OrderService.placeOrder()` to submit an opposite-direction market order
- Show success/error toasts and refresh dashboard data after submission
- Add row-level loading state with spinner during API call

### Discovery References

- **Close = opposite market order**: `PlaceOrderRequest { asset: position.asset, side: opposite, orderType: "market", size: Math.abs(position.size) }`
- **Position side mapping**: `Position.side` is `"Long"` or `"Short"` (title-case from API). `PlaceOrderRequest.side` is `"buy"` | `"sell"`. Mapping: `Long → "sell"`, `Short → "buy"`
- **Position identity key**: `position.asset + position.side` (existing track expression, unique per position)
- **No new backend work**: `POST /api/orders` already handles market orders with slippage, signing, and error responses
- **Existing patterns**: `OrdersTableComponent` → `DashboardComponent` event pattern with row-level loading, confirmation dialog, snackbar toasts, and `_refresh$.next()` for polling reset

### Project Patterns

- `frontend/trading-ui/src/app/features/dashboard/orders-table/orders-table.component.ts` — Row-level loading state via `Set<string>`, `@Output` event emitter pattern
- `frontend/trading-ui/src/app/features/dashboard/orders-table/orders-table.component.html` — Actions column with conditional spinner/buttons
- `frontend/trading-ui/src/app/features/dashboard/dashboard.component.ts` — Dialog, API call, snackbar, `@ViewChild`, `_refresh$` trigger, `_pendingOrderIds` optimistic update pattern
- `frontend/trading-ui/src/app/features/order-entry/confirm-dialog/confirm-dialog.component.ts` — Reusable `ConfirmDialogData` supporting both simple title/message and structured order summary modes
- `frontend/trading-ui/src/app/core/services/order.service.ts` — `placeOrder(request)` method to reuse
