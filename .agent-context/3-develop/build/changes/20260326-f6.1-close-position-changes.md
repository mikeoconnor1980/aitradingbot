**Related Plan**: 20260326-f6.1-close-position-plan.instructions.md

## Summary

Add a "Close" button to each open position row in the positions table, allowing the user to close a position by placing an opposite-direction market order for the full position size. Frontend-only changes reusing the existing F5 order placement endpoint.

## Design Decisions

<!-- Phase 1: Positions Table — Close Button & Loading State -->
- Kept loading key identity as asset + side to match existing row tracking and phase specification.
- Applied pointer-events: none on loading rows to block duplicate actions during in-flight close operations.

<!-- Phase 2: Dashboard Integration — Close Handler & Wiring -->
- Used the same optimistic-update and pending-set guard pattern already used for order cancellation/modification to keep behavior consistent.
- Used position key format `asset + side` to match existing row identity in PositionsTableComponent.

## Release Summary

F6.1 Close Position is fully implemented. A Close button has been added to each row in the positions table. Clicking it opens a confirmation dialog showing the asset, side, and size with a note that a market order of the opposite direction will be placed. On confirmation, the order is submitted via `POST /api/orders` using the existing `OrderService.placeOrder()`. Row-level spinner + disabled state prevents duplicate submissions. Success shows a toast and resets the polling refresh cycle; errors show a meaningful error toast. The feature requried changes to 5 files (3 in PositionsTableComponent, 2 in DashboardComponent) with no new dependencies and no backend changes.
